## 2. 模块拆解（第 2 层）

### 2.1 loader（收货登记处）

输入一个 LeRobot v3 数据集目录，输出内存中的完整数据模型。核心麻烦是**两套编号空间**：parquet 文件分块存储（`data/chunk-000/file_000.parquet`），文件内 `episode_index` 是块内局部编号；`meta/episodes.parquet` 是全数据集全局编号。`_reconcile_episode_ids` 负责建立映射（精讲见 §3.1）。铁律：**永远只读**。

### 2.2 validator（质检员）

**自适应阈值 median ± k·1.4826·MAD**：不用固定数字（不同数据集正常帧数差异巨大），按数据集自身分布推导。用 MAD（中位数绝对偏差）而非标准差，因为标准差会被极端值自己抬高自己；1.4826 是正态分布 σ≈MAD×1.4826 的换算常数，让 MAD 尺子刻度与标准差对齐，k 沿用"±3σ"直觉。落地实现见 §3.2。

**规则与量刑**：13+ 条规则（论文口径 31 条 = 19 条 episode 级 + 4 条数据集级 + 8 条点云），severity 分 info / warning / error。结构性不一致（frame_mismatch / video_span_mismatch，即 parquet 说 300 帧视频实际 297 帧）是 error——第四幕 29 个被 drop 集的名义罪名（2026-11-21 双 take 尺子修复后确认其中 20 集是误报、重裁为 repair，见 §4.8）。

**三条执行路径**：全量内存 / 流式（大数据省内存）/ ProcessPool 并行。约束：并行与串行**逐位一致**。

### 2.3 policy（分拣台）

- **systemic guard（按规则熔断）**：单条 error 规则命中率 ≥95% → 该规则的 drop 全部降级 review（§3.3）。防"规则对某类机器人系统性误报时错杀整批"。
- **mass drop guard（按总量熔断）**：多条规则各命中一部分、整体剔除比例过高时，全部 drop 降级 review。
- **人工复核回路**：review 集 → review_queue.csv → 人用 `--overrides` 传裁决 → 重跑生效。机器永不替人做"丢数据"的终审。
- 软规则（如 state_jump）永不自动剔除，只送 review。

### 2.4 cleaner（洗涤车间，第四幕翻车现场）

三条纪律：
1. **源数据严格只读**：输出写独立 `cleaned_dataset/`，原始目录一个字节不碰——保证"洗坏可重来"。
2. **自检闭环**：洗完重跑规则引擎（verify）——用当初抓它的尺子再量一次。
3. **drop-only 重排机器**：按处置清单重排数据集的通用机器，干净到被 Kaggle 实验脚本直接复用。

危险动作 `_concat_segments`（视频分段重编码+拼接）：第四幕两个 bug 均在此（§3.4）。

pts（presentation timestamp，播放时间戳）：视频每帧自带的"第几毫秒被显示"标签；机器人学习靠它对齐画面帧与动作指令，错 1 帧都是事故（33ms@30fps 恰为一帧）。

**新能力（2026-11-20，commit 9e95e6e）——split/window 拆分修复**：这是"结构不一致→repair 而非 drop"政策的代码落地。`policy.decide` 在 repair=split/window 时生成拆分计划，cleaner 跨文件扫描（`_source_files_in_order` / `_episode_row_index`，meta 行序反序、NULL episode_index 均容错），meta 按 output_plan 多段生成连续新编号——把"超长/跨文件的坏数据"**拆成多个合法 episode 或按窗口裁剪**，而不是整段扔掉。同 commit 还堵了三个"静默丢失"洞：处置解析静默丢 repair（缺 repair 子类型时降级为 index 重建 + 显式 warning，不再当 keep）、缺列静默跳过（set_column 改为 append）、字符串 episode_index 的 filter 不命中——全部改为**不静默**，呼应 §3.5 第 4 条设计思想。

**第 2 层检验题**：① 为何用 MAD 不用标准差？1.4826 干嘛的？② systemic guard 防什么错、写反会怎样？③ "源只读+verify"与 pts bug 的因果？
**答案**：① 标准差被极端值自己污染，MAD 抗极端值；1.4826 把 MAD 刻度换算回标准差刻度。② 防"元数据系统性错配→错杀整批"；写反则一条天然误报的规则即可不可逆删除全部数据。③ verify 让 bug 能被发现（探测器+外部客户端双重暴露），源只读让修复后能重洗 B′——没有这两条，bug 会静默污染且无法重来。

## 3. 逐函数精讲（第 3 层）

### 3.1 `_reconcile_episode_ids`（loader.py:1098）—— 宁可不对账，不可猜错账

决策阶梯（每步失败即退回，绝不猜）：

```
两侧编号集合相等   → native，不映射          (loader.py:1138)
数量不等          → ambiguous（无法一一对应） (loader.py:1142)
data 编号非升序    → ambiguous（顺序配对不可信）(loader.py:1150)
顺序配对证据不足   → ambiguous（不猜测映射）   (loader.py:1199)
全部通过          → remapped                (loader.py:1208)
```

证据（loader.py:1157-1194）：顺序配对后逐集核对 ① 行数 vs meta 声明 length；② 视频窗口×fps vs 行数。合并：

```python
agreement = min(evidence) if evidence else 0.0    # :1194
```

**证据合并用 min，不用平均**——最弱证据定生死。min_agreement=0.99；低于即 ambiguous 转人工。猜错的映射会把视频窗口、任务全部错配，比不映射更危险。

### 3.2 validator 阈值推导（validator/context.py:153-182）—— MAD 的落地形态

```python
mad = np.median(np.abs(counts - median))          # :153 尺子
if mad > 0:
    sigma = 1.4826 * mad
    auto_low  = max(floor,   median - 3.0 * sigma) # :181 短侧紧
    auto_high = min(ceiling, median + 8.0 * sigma) # :182 长侧松
```

两个不对称：
- k 不对称（低 3σ / 高 8σ）：比中位数短常是截断丢数据（危险），长多半是多录（无害）；
- 夹在 [floor=8, ceiling=20000]：自适应尺子也要有安全边界，防小数据集 MAD 退化。

**mad == 0 分支**（全数据集每集帧数一样，MAD 塌缩为 0；tokyo 实测 239×47+237+238）：`b8e00d7` 加最小宽度：

```python
mad0_half = max(1, ceil(0.01 * median))   # 239 帧 → ±3
auto_low, auto_high = median - mad0_half, median + mad0_half
```

**为什么不能用观测 [min,max] 当边界**：被判定样本自定义边界 = 零检测。反例 49×239+1×100：用观测 min/max 则 100 帧截断集永远合规。检测边界不能由被检测对象定义。

### 3.3 `_apply_systemic_guard`（policy.py:167）—— 20 行的熔断器

```python
hits[code] += 1                        # :181 每条规则贡献的 drop 数
share = count / total                  # :185
if share < SYSTEMIC_HIT_RATIO(0.95): continue
d.disposition = "review"               # 降级，不执行
d.source = "systemic-guard"            # 留痕
```

docstring 价值观（policy.py:171）："删数据不可逆，所以这里选择**阻断而不是执行**。" 它不是唯一一道闸——`_apply_mass_drop_guard`（policy.py:205）按整体剔除比例再熔一次（防 5 条规则各命中 20% 合计删 80%+）。类比：回路保险丝 + 总闸。两道闸都只降级、永不自动反向——终审在人。

### 3.4 `_concat_segments`（cleaner/manual.py:558）—— 浮点对视频抠帧的险地

docstring 即验尸报告（manual.py:561-574）：

| bug | 机理 | 表现 |
|---|---|---|
| `-t` 时长截断 | 帧 pts=k/fps 是无限循环小数（430/30=14.3333…），`-t` 有限小数只要略小于精确时长就丢末帧 | "部分集各丢 1 帧"，原因不明多年 |
| `-ss` 后 pts 不归零 | ffmpeg 寻址后不重置输出时间戳，from_ts>0 的段首帧 pts 恒偏 1 帧（33ms@30fps） | B@4000 FrameTimestampError 崩溃 |

修复三件套（manual.py:582-587）：

```python
expected = max(int(round((to_ts - from_ts) * fps)), 1)  # ① 帧数按整数算死
ss = max(from_ts - 0.5 / fps, 0.0)                      # ② 定位点提前半帧
cmd = ["-ss", f"{ss:.6f}", "-i", src, "-frames:v", str(expected),
       "-vf", "setpts=PTS-STARTPTS", ...]               # ③ 硬截断 + pts 归零
```

- **②提前半帧**：寻址点落在（上一帧 pts, 本帧 pts] 安全区间中点；6 位小数舍入误差 ~3e-7s 远小于半帧 1/(2·fps)≈0.017s，首帧绝不跳过。
- **③ -frames:v 替代 -t**："掐秒表"改"数格子"，浮点出局。
- **setpts=PTS-STARTPTS**：每段胶片重新从 0 打孔（65fa94a 核心一行）。

防御纵深（manual.py:595-611）：切完 `probe_video_frames` 数实得帧数，不符即告警"源视频时间戳可能不规则"——不静默。失败路径宁可少不可错：切片全失败→原样复制+告警；拼接失败→只留第一段+告警。

### 3.5 六条设计思想（四个函数共享）

1. **宁可 ambiguous 不可猜**（映射退回不猜测）
2. **证据合并用 min**（最弱证据定生死；doctor 用 mean → 3 FN 的反例）
3. **不可逆操作必须阻断**（熔断只降级，人做终审）
4. **不静默**（一切异常告警留痕：source / note / warnings）
5. **浮点问题用整数化解**（-frames:v、帧号对账）
6. **检测边界不能由被检测对象定义**（mad0 最小宽度）

**第 3 层检验题**：① min vs 平均的现实反例？② 最小宽度取 0.01% / 10% 各会怎样？③ -ss 提前半帧与 -frames:v 各管哪半边？
**答案**：① 100 集行数全对（1.0）但视频窗口 98% 对（0.98）：平均 0.99 放行、min 0.98 拦下——2% 错位可能是映射从某集开始整体错位的最早信号。② 0.01%→容差 1 帧，±1~2 帧抖动重新误报（白修）；10%→±24 帧，真实截断混入漏检（尺子失效）；1%→±3 帧居中（config.py:41 注释原话：覆盖 ±1~2 帧录制抖动、截断级离群仍在界外）。③ -ss 提前半帧管"起点准不准"（首帧必包含），-frames:v 管"终点够不够"（整数帧硬截断）；两者合堵 bug1 的丢首/丢尾，bug2 由 setpts 管。

### 4.3 策略结论（无论第二轮谁赢都成立）

- 29 个 drop 集全是**结构性不一致**（parquet 与视频计数不匹配），(s,a) 监督对仍然有效；
- 在 <1.1 epoch 的训练区间里，"结构不一致=丢弃"**净效应为负**；
- 处置政策应改为：**元数据级不一致 → repair，内容级损坏 → drop**；
- 本次第一轮测的是"清洗管线整体产物 vs 最小修复"——管线自己的机器损伤（漂移）污染了对照；修复后再跑才可能把差距归因到 drop 策略本身。

> **v2 复跑 + 多 seed 已把上面的推断变成实测结论**（见 4.4–4.6）：漂移修掉后 A 仍赢且差距扩大，方向跨 seed 稳健。

### 4.4 v2 复跑（2026-11-19~20）：同 epoch 裁决——A 仍然赢，且赢得更大

漂移修掉、pts 全归零的 B′ 重训后，裁决口径（同 epoch ≈1.0）：

| 对比 | A | B′ | A−B′ | SE | t |
|---|---:|---:|---:|---:|---:|
| **A@010000（1.00 ep）vs B′@007000（1.01 ep）** | **0.23688** | **0.25782** | **−0.02094** | **0.00384** | **−5.45** |

- 差距比 v1 的跨 step 口径（−0.0096）**扩大**到 −0.0209 → v1 结论在修复后的 B′ 上不仅复现、还更强。
- **归因更新**：P1 修复后"cleaner 重建损伤"成分已消除（帧数差 0/34、pts 34/34 归零），差距仍存在 → 净值差异主要来自**数据量/覆盖**：B′ 少 31.5% 帧、少 29 集。
- **曲线机制**：A 在 8k 步（0.79 ep）进平台（0.2378），B′ 在 6k 步（0.86 ep）进平台（0.2578）——平台出现时间几乎一致，**不同的是平台高度**。B′ 看似"更早饱和"只是因为它每 epoch 步数少（7k 收官=1.01 ep）叠加 cosine LR 到 7k 归零。
- **+1428 复核推翻**：早先"A 的坏集自身窗口超界 +1428 帧"是误读。逐文件核对：源 meta 的 172 个窗口在 12 个视频文件上**无缝铺满**（160 对相邻窗口间隔全为 0 帧），1428 = eval 留出帧（1,132）+ 末个 take 录制尾巴（296），都不在任何训练读取区间内。据此 **D 臂（只修 9 个超长窗口）确认是 no-op，取消**。

### 4.5 多 seed 复验（2026-11-20）：预注册三档判读，方向稳健

SE=0.00384 只含评测窗口噪声、不含训练随机性——所以**先预注册三档判读（跑之前写死）**，再补 seed 1/2：

| seed | A@10k | B′@7k | diff | t |
|---:|---:|---:|---:|---:|
| 0（历史） | 0.23688 | 0.25782 | −0.02094 | −5.45 |
| 1 | 0.23328 | 0.25479 | −0.02151 | −3.51 |
| 2 | 0.23399 | 0.25122 | −0.01724 | −4.66 |

判读由 `analyze_seeds.py` 机械执行：**档 1 成立**（三个 seed 全负）→ 报 **−0.0199 ± 0.0023**（mean ± cross-seed SD）；档 2（任一反号降级）与档 3（SD≥|mean| 视为不可分辨）均未触发——SD 与 |mean| 比值约 8.6，0.021 的差距在 seed 噪声下仍可分辨。

**口径修正**（下载后核对）：seed 1/2 的评测实际只有 **40** 个窗口（seed 0 是 320），三臂 SE 非同口径，t 值仅作参考；跨 seed 的 mean/SD 不受窗口数影响。四臂权重已归档 `G:\ab\`（每份 906,712,552 B、500 tensors、header 与实际长度一致）。

### 4.6 本轮最重要的方法论课：epoch 混淆

两臂每 epoch 步数不同（A≈10,154、B′≈6,954）。**按 optimizer step 对比会得出与按 epoch 相反的结论**：

- 同 step 口径：5k 时 B′ 反先 0.0094 → "清洗更好？"；
- 同 epoch 口径：A 在 0.58 / 0.72 / 0.86 / 1.01 ep 上分别低 0.026 / 0.024 / 0.021 / 0.021 → **清洗从未占优**。

> 类比：两个学生刷题，A 每天刷 50 题、B 每天刷 34 题。第 5 天 B 的正确率暂时高——不是 B 方法好，是 B 已经刷了 170 题、A 才 100 题。**比较必须先对齐"看过多少数据"（epoch），而不是"刷了几天"（step）。**
> 附带结案：v1 里"5k 处曲线骤平"曾被疑为数据效应，实为 cosine LR 调度终点（5k）所致——**调度决定走平位置，与数据无关**。

### 4.7 坏/好窗口实验（badgood）：量化"脏样本可学习性"

冻结 eval 的 320 窗口全部来自清洗**存活**集，天然做不了坏/好对比。三步走：

1. `make_badgood_windows.py`（本地）：从 A 的 157 块里另抽两组窗口——**bad** = 29 个 drop 集的块（含 22 个双拷贝块）、**good** = 其余训练块，各 40 个，分层抽样口径与 eval 冻结件一致；
2. `eval_badgood.py`（Kaggle kernel）：对 A/B′ 两臂在 80 个新窗口上同窗口同 batch 顺序同噪声种子逐窗口配对评测；
3. `analyze_badgood.py`（本地）：**DiD = gap_bad − gap_good** 判读。

> **DiD（差中之差）为什么能隔离"脏"？** 两臂在 good 窗口上也有差距（那是数据量的整体效应），bad 和 good 两组差值**相减**，把共同效应抵消掉，剩下的就是"脏样本额外损失的可学习性"——如果 DiD≈0，说明被 drop 的 29 集**并不比好数据更难学**，drop 丢的纯属白丢。

**结果（2026-11-21，本地 CPU 跑通，没花 Kaggle 额度）**：DiD = **−0.04614 ± 0.01226（t = −3.76）**，三岔判读触发第一岔——坏集 (s,a) 可学习，repair-not-drop 定量坐实。bad 组 gap = −0.0559 ± 0.0107，good 组 −0.0098 ± 0.0060（不显著，排除臂质量解释）。运行环境 `G:\ab\badgood_local\venv312`（py3.12 + lerobot 0.7.0 源码 + torch 2.15.0+cpu，与 Kaggle 训练同版本）；数据/权重/windows 全为原件；eval_badgood.py 已双端化（BADGOOD_* 环境变量）。产物 `G:\ab\badgood_results.json`，判读脚本 analyze_badgood.py 机械执行，已回填 results.md/论文 §6.2/EVAL。

### 4.8 第五幕收尾：双 take 尺子修复与 29 集重裁（2026-11-21，commit ad33a9e）

DiD 定量坐实"坏集可学习"之后，判定侧根因同步落地——**双 take 尺子**：

- **根因**：ep81-102 这 22 个集，同一 episode_index 在 meta/episodes 有两行（每行自带 length 与视频窗，甚至不同视频文件），parquet 行数 = 各段之和。旧尺子只取第一行窗口比全集行数——564 行的 take1 窗口对 944 行全集，正常双 take 被系统性误报成 frame_mismatch(error) + video_span_mismatch。
- **修复**：loader.video_locations 按段返回全部窗口；validator 四处判定（video_span/帧数/时间戳漂移/frame_index）改按段计量（"按 take 量"）；并行 worker 同步拿到未去重 meta 段行（与串行口径一致）。
- **真值验收**：bomb 全量前后对比——20 个双 take 集精确摘除两条幻影、零新增 flag；仍有 error 级的 9 集（19/23/47/68/69/84/98/120/126）与块级拆分重建产物上的判定**逐集一致**——修好的尺子在原始数据上复现了真值口径。
- **重裁**：29 个曾被 drop 的集重裁为 **29/29 = repair、零 drop**（22 split + 7 window 收窄），用户签收转正（annotation/drop_relabel_worksheet.csv，label_source 记录 provenance）。旧定性"9 集全内容级缺陷"同时被推翻——那 7 个单段集全是窗口尾巴问题（收窄即修）。

> 类比：体检仪的探头只看了第一张切片就下了"全阳"结论。修探头不是改结论——是把"全阳"重读成"两段各自阴性"。**判定单错了，处置白搭**：先修尺子，重裁才有意义。run_pool 顺带修复（BrokenProcessPool 串行回退丢任务洞，点云 workers=4 偶发失败根因，回归测试钉死）。

**闭环账本**：①现象（三臂全负）②机制（DiD）③诊断（尺子盲区+处置过狠）④处方落地（split/window+尺子）——四环闭合；**未闭合 = 处方级验证**：repair 产物重训三臂对照（C 臂），GPU 30h 额度现成、cleaner split 链路现成，待做。

## 6. 术语表

| 术语 | 一句话解释 |
|---|---|
| pts | 视频帧的播放时间戳（第几毫秒显示）；训练靠它对齐画面与动作 |
| MAD | 中位数绝对偏差；抗极端值的"标准差替代品"，×1.4826 换算回 σ 刻度 |
| severity | 规则量刑：info / warning / error |
| disposition | 处置：keep / repair / review / drop |
| systemic guard | 单规则命中率 ≥95% 时的熔断降级（drop→review） |
| mass drop guard | 整体剔除比例过高时的总量熔断 |
| wrap（±π 卷绕） | 角度过 ±π 边界数值跳变但物理连续（+π→−π，Δ≈2π） |
| 成对尖峰 | 连续两帧互抬邻域中位数导致漏检的尖峰形态（fps 低时窗口塌缩） |
| 帧漂移 | 重建视频后帧数/时间戳与 parquet 声明不一致（−1~−13 帧、pts 偏 33ms） |
| tolerance_s | 训练框架允许的帧时间戳误差上限（0.01s；漂移 33ms 即崩） |
| epoch / ckpt | 完整过一遍训练集的次数 / 训练中间存档 |
| flow-matching loss | SmoVLA 这类流匹配策略的训练目标，越小=预测动作流越贴真值 |

| epoch 混淆 | 两臂每 epoch 步数不同（10,154 vs 6,954），按 optimizer step 对比与按 epoch 对比结论相反——比较必须先对齐"看过多少数据" |

| badgood | 坏/好窗口实验：从 A 抽 40 坏（29 drop 集的块）+ 40 好，两臂同窗口配对评测后做 DiD |
| MotionClip / GaitClip | gait_unit 两级 IR：通道级表格（T×D+通道名）/ 骨骼级立方体（T×J×3+关节父子关系） |

| 四元数 q≡−q | 四元数与它的相反数表示同一姿态；整体符号翻转是表示等价而非缺陷（与主线 state_wrap 卷绕豁免同哲学） |

## 8. gait_unit：步态/光捕数据质检的第二产线

### 8.1 它是什么、为什么单开一条线

主线 pipeline/ 处理的是"机器人看得见的帧表"（RGB 视频 + state + action）。**光捕（光学动作捕捉）数据是另一种东西**：没有视频，是骨架关节角随时间的数值轨迹，120Hz、通道语义明确（如 `dof_left_knee_joint(rad)`）、最终要"穿"到某个机器人骨架（如 G1 的 29 关节）上。规则对象和文件格式都不同，所以单开 `src/lerobot_data_quality/gait_unit/`，与主线**零代码依赖、零格式依赖**，只共享设计范式：MAD 自适应阈值、缺陷注入验收、manifest 留痕、"规则先有靶子再写实现"。

> 类比：洗衣厂旁边开了一家**皮具护理店**。工具不同（不能用洗水机洗皮衣），但经营哲学相同：先登记、用抗极端值的尺子、宁可送人工不乱猜、坏了能追溯。

### 8.2 两个中间表示（IR）——数据的两种"登记形态"

- **MotionClip（通道级）**：T×D 的表格 + 通道名元组。承认"我只有一堆数值通道+名字"这一事实，任何 1-DOF 关节角轨迹都装得进来。缺陷（NaN、跳变）**原样保留**进 IR，`validate_motion()` 只做结构层校验（形状/Inf/fps）——质检前不动数据一根汗毛。
  > 类比：一张 Excel 表，每列一个关节的角度，每行一个时刻。
- **GaitClip（骨骼级）**：T×J×3 的立方体 + 关节父子关系（parents）+ 可选局部旋转四元数。每个时刻每个关节有全局位置，骨头连着骨头。
  > 类比：木偶的骨架——不仅知道每根关节转了多少度，还知道手在哪里、脚在哪里。

MotionClip 的通道能映射到骨架时，经 URDF 运动学正解（FK）**升级**为 GaitClip。

### 8.3 四个数据源适配器（四个翻译官）

| 适配器 | 来源 | 特点 |
|---|---|---|
| `motiondecode.py` | 青瞳视觉重定向后的 G1 29 DOF 关节角 CSV（120Hz） | 机器人视角的关节角 |
| `bvh.py` | 公开数据集（LAFAN1）BioVision 层级格式 | 动画行业骨架文件，含骨骼层级+旋转；实测需 scale=0.01 与 up 轴声明（a6c12ed 加固） |
| `fzmotion.py` | 动捕系统导出长表（timestamp, marker_id, x, y, z） | 标记点视角的原始坐标 |
| `pico_csv.py` | PICO 设备导出的原始采集 | VR 设备视角（另有 tools 里 Pico 上传 Bug 数据集构造脚本 c2ab43f） |

四个来源格式各不相同，适配器统一翻译成 MotionClip/GaitClip——**后面的规则只对 IR 说话，不关心来源**，新数据源只需加一个翻译官。

### 8.4 三层 Tier 规则（体检的三级科室）

| Tier | 代码 | 查什么 | 例子 | 类比 |
|---|---|---|---|---|
| Tier 1 通道级 | `qc_rules/channel_rules.py` | 单通道数值异常 | MAD 跳变、NaN 段、常值通道、四元数整体翻转 | 血常规（一项一项查） |
| Tier 2 关节级 | `qc_rules/skeleton_rules.py` | 关节物理合理性 | URDF 限位超限（膝盖不能反向弯 180°）、角速度尖峰按动作类别分档 | 骨科（逐关节查活动度） |
| Tier 3 空间级 | `qc_rules/spatial_rules.py` + `point_rules.py` | 整体空间合理性 | 骨长一致性（大腿骨不会一会儿 40cm 一会儿 45cm）、marker 点离群、接触点合理性、质心波动 | 全身影像（整体协不协调） |

两个 Tier 1 亮点：
- **120Hz→30Hz 折算（scale_frames）**：主线阈值按 30Hz 标定，120Hz 光捕的"每帧变化量"天然只有 1/4，不折算则规则在光捕上全面过松/过紧。
- **四元数整体翻转识别**：q 和 −q 表示同一个姿态（类比 +180° 和 −180° 是同一个朝向），整体符号翻转会产生 ~2|x| 的"假跳变"——逐帧检测后**自动豁免**；只翻单个维度的仍是真跳变。与主线的 state_wrap 卷绕豁免是同一个哲学：**表示等价 ≠ 数据缺陷**。

### 8.5 校准：LAFAN1 77 段"本底报警率"

规则好不好，先要在"确认正常"的数据上看它**误报多少**。gait_unit 在 LAFAN1 公开数据集的 **77 段 BVH** 上全量跑完，按动作类别（aiming/dance/fallAndGetUp…）建立**本底报警率表**（`reports/gait/lafan1_calibration.json`，含 provenance：scale=0.01、up_axis=y）：校准表实数（k=6，/千帧×关节）：push 8.6、walk 21.3、dance 33.5、jumps 45.3——正常数据不全绿，报警率随动作动态性单调上升。跨数据集泛化验证与全库注入基准（2026-11-21）见 §8.8；全量基准明细 `lafan1_benchmark_full.json`（77 段 × 385 注入，旧 8 段明细已删）与 MotionDecode v1 报告 `motiondecode_v1.json` 同目录留痕。

> 类比：新体温计先在一群健康人身上量一遍，记下"健康人也会被标 4% 的读数"这个本底；以后判断病人时先扣掉本底，再谈发烧。

### 8.8 两个数据集实验（2026-11-21，EVAL §12/§13）

**实验二·泛化验证**：chingmu_subset 20 集 + 零重叠古典舞 18 集（均为厂商重定向 120Hz 1-DOF）vs LAFAN1 校准表，k=6/8/10/12 同口径对照，episode↔源分类确定性映射。判读**按类别分化**：dance 两域报警率几乎重合（33.5 vs 33.6/36.8，全 k 落带内）；jumps 14 倍偏差（3.28 vs 45.29，全 k 落带外）——厂商平滑掉了原始动捕冲击噪声。附带发现 **mad_jump 双峰语义盲区**：静态为主+局部运动的集，全集 MAD 被静态段压扁，正常运动段 z 可达 10²（ep17 归因：原始通道最大帧差仅 3.6°/帧）——滑动窗口 MAD/长 run 降级入改进清单。**全库 69 集 dance 复验**：池化 35.77/25.23/20.47/17.31，全部 k 落带内（EVAL §12.5，含两条分析错误订正记录）。

**实验一·注入基准全量化**：LAFAN1 全库 77 段 × 5 trials = 385 次注入 × k 扫描。dup 1.0、frame_drop 0.948（漏检全在 n=2 最小注入）、drift 0.9 与 k 无关（累积漂移终过阈——**H2 拒绝，修正"查全优先"表述**）、joint_limit 按类别 0.0-0.667（sprint/fightAndSports 0.0）；precision 全 k 全类 1.0、误报 0（基线解释机制规模化成立）。

> 检验题：为什么厂商数据上注入基准的查全率是"能力上限"而不是"现场表现"？→ 注入缺陷落在平滑底片上（MAD 小、信号孤立），真实缺陷缠在活跃运动里且互相叠加——ep17 的双峰盲区就是现场形态的预演。所以注入测能力，真实数据测表现，两者缺一不可；而真实缺陷数据的瓶颈永远是标注。

## 11. 测试是怎么设计的（61 文件 / 429 tests，pytest collect 实测）

### 11.1 十条设计模式

1. **自造世界的夹具**（conftest.build_dataset）：临时目录用 pyarrow 写出最小可用 v3 数据集（无视频、无 ffmpeg 依赖），单测秒级且零外部依赖；带视频的全链测试才用 demo_dataset（36 集注入 13 处异常）。
2. **两侧对称**（test_validator.py，33 tests）：docstring 原话——"每条规则都要有「命中」和「不误报」两侧的用例"。假阴性和假阳性双向覆盖：只有命中侧的规则测试 = 不知道它会不会乱咬。
3. **事故即测试（回归档案）**：每次真实翻车固化成一个测试文件——pts 33ms 崩溃 → test_cleaner_concat_frames.py（参数化剔尾/剔首，断言帧数精确 + 首帧 pts 归零 + 漂移<半帧）；±π 卷绕 → test_state_wrap.py（docstring 写明"端点判据刻意不用整维值域"的教训）；成对尖峰 → test_action_jump_paired_spikes.py；MAD=0 → test_frame_count_mad0.py；跨文件修复 → test_cleaner_cross_file_*.py；BrokenProcessPool 丢任务洞 → test_parallel.py（两个缺口：先 pop 后 result、submit 瞬间破裂）；双 take 尺子盲区 → test_dual_take_ruler.py（7 条，含并行一致性）。**测试文件即事故档案**。
4. **先红后绿**：修 bug 流程 = 先写暴露 bug 的测试（红）再修（绿）——G4/G5 修复全部如此，防"修复本身没被验证"。
5. **逐位一致并发**（test_parallel.py）：核心断言一条——**workers>1 与串行逐位一致**；顺带验证 spawn 下 worker 可 pickle。"并发只改变在哪里算，不改变算什么"。
6. **毒数据注入**（test_fault_tolerance.py）：把合法 parquet 头尾改写成垃圾字节模拟磁盘坏块/写一半，断言不崩溃、隔离、退出码正确——docstring 连"如何伪造损坏"都教学了。
7. **指纹全覆盖**（test_incremental.py，18 tests + test_reporter_fingerprint.py）：manifest 指纹失效条件逐条测（数据变化/配置变化/mtime），stat 失败不崩溃——增量复用的"复用错了比重跑更贵"风险被测试钉死。
8. **诚实边界测试**：连"没查"都有专门测试（test_validator_skipped_semantics.py）——skipped 语义也要测"没查得对"；gait_unit 基准 harness 把规则查全/精度变成可测量指标（§8.7）。
9. **可复现注入基准**（test_gait_unit_benchmark.py）：真实底片 + 随机注入带地面真值 → 查全/精度，seed 固定可重复。
10. **分层金字塔**：规则函数单测（临时夹具）→ 全链集成（demo_dataset 13 处异常全命中 0 误报）→ 真实外部数据端到端（EVAL.md 记录口径）。

### 11.2 测试文件分类地图

validator ~15 文件（validator/frame_count_bounds/mad0/wrap/paired_spikes/skipped_semantics/action_distribution/alignment/audit_hardening/dual_take_ruler…）｜cleaner ~8（matrix/concat_frames/cross_file×2/repair_split_window/stats/timestamp_scope/empty_episode）｜loader ~6（edge_cases/reconciliation/order_guard/meta_missing/max_episodes…）｜gait_unit 8｜基础设施 ~12（config/schema/versions/precheck/card/dashboard/tuning/nonstandard_fields）｜点云 / 容错 / 并发 / 增量 / 导出。

## 12. 具身智能：这个项目在大图景里的位置

### 12.1 什么是具身智能

智能不只来自符号运算，还来自**身体与环境的实时交互**——"要理解彩虹，得先摸过雨"。互联网 AI 是旁观者（读别人写的文字、看别人拍的图），具身智能是第一人称的：**动作有物理后果**，撞了桌子就是撞了。机器人不是"先想清楚再动"，而是从交互数据里学"什么状态下该输出什么动作"。

### 12.2 三条技术路线

| 路线 | 怎么学 | 短板 |
|---|---|---|
| 强化学习（RL） | 试错+奖励 | 样本效率低；仿真到真机（sim2real）有鸿沟 |
| 模仿学习（BC→扩散/流策略） | 从人类演示学 | **数据饥渴**——演示多少学多少 |
| VLA 大模型（RT-2 / OpenVLA / π0 / SmolVLA） | 预训练视觉-语言底座 + 机器人动作头，少量演示泛化 | 依然吃数据质量 |

### 12.3 模仿学习的"燃料"形态——LeRobot 格式

每个数据集 = 多次任务演示（episode）；每帧 =（这帧画面 + 这刻关节状态）→（这刻该输出的动作）。训练 SmolVLA（450M VLA）用 **flow-matching loss**：模型学"从纯噪声出发、沿一条流走向正确动作"——每一步往真值动作方向修一点（类比：眯眼看图从模糊到清晰）。评测用 hold-out loss 是**代理指标**，真指标是真实 rollout 成功率——这是 A/B 实验的第一保留意见。

### 12.4 数据为什么是第一性瓶颈——本项目存在的理由

互联网数据可以爬，机器人数据**只能录**：1:1 时间成本（录 1 小时要 1 小时）、真机折旧、场景搭建。LeRobot 生态 150+ 数据集、10+ 种机器人硬件，格式统一了但**质量无人把关**；采集中断/丢包/遮挡/视频错位/NaN 在真实采集里不可避免。

> **供应链定位**：传感器 → 采集 → **【质检+清洗 = 本项目】** → 训练 → 部署 → 遥操作接管数据回流 →（回到质检）。这是数据飞轮中"采集→训练"之间的一环——接管段产生的 action 跳变正是飞轮自己的污染物，绕一圈又回到质检站。

A/B 实验的领域级意义：在欠训练区间，"数据覆盖 > 结构完美"——**"什么数据该删"是具身智能数据治理的核心权衡**，本项目给出了首个同 epoch 量化答案（保留：单数据集、1 epoch、代理指标）。

### 12.5 gait_unit 在图景里的位置

操作臂数据来自机器人本体遥操作；**人形**全身运动来自动捕/VR 采集——人穿动捕服走路，再**重定向（retarget）到机器人骨架**。gait_unit 管的是这条链的输入质检；G3 retarget 是链上的转换环节（门控中，见 §8.6）。一句话：操作臂管"手"，gait_unit 管"腿"，两条腿的数据 eventually 都要变成同一种 (观察→动作) 燃料。
